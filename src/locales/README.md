# `src/locales/` conventions

This directory holds only the shared app-shell catalog: English (`en.json`)
plus its Spanish (`es.json`) and German (`de.json`) translations. Feature copy
lives beside its feature at `src/features/<feature>/locales/{en,es,de}.json`.
The loader discovers those shards automatically and merges them in stable path
order. Stream E owns the i18n pipeline.

## File roles

| File | Role | Editor |
|---|---|---|
| `en.json` | Shared shell/common source of truth. | Hand-written by humans. |
| `es.json` | Shared shell/common Spanish (es-ES) translations. | Generated by `scripts/translate-i18n.mjs`; human reviewers may lock individual keys. |
| `de.json` | German (de-DE) translations. | Same as `es.json`. |

## Namespace layout

Top-level namespaces remain lowercase kebab-case. Put a namespace in the
feature that owns it, not in these shared files. A feature shard keeps its
normal top-level namespace so existing `t('namespace.key')` calls do not
change. The shared base is reserved for shell and cross-feature copy:

```
app commands common layout quick-open shortcuts-overlay spine tab-guard updater
version whats-new
```

`common` is reserved for vocabulary reused across more than one feature
(`common.actions.create`, `common.trash.empty-confirm_other`, etc). Avoid
adding feature-specific copy here. If a string only appears in one feature,
put it under that feature's namespace.

## Naming convention

Keys follow `<page>.<component>.<element>` in lowercase kebab-case:

```
chat.input.send-button
settings.api-keys.title
marketplace.templates.install-cta
common.actions.create
```

Rules:

- Lowercase ASCII letters, digits, hyphens. No camelCase or snake_case
  segments.
- Two segments minimum (`<namespace>.<element>`); three or more for nested
  features.
- Avoid generic suffixes like `.text` or `.label` unless the surrounding
  context needs disambiguation (`error-message-text` versus `error-toast`).

`tests/unit/i18n/en-json-snapshot.test.ts` discovers shard inventory instead
of using a hand-maintained total. It verifies English, Spanish, and German
have the same feature shards and leaf-key shapes, and that duplicate leaf keys
fail during the deterministic merge.

## Plurals (CLDR)

i18next picks the variant based on the count value via CLDR plural rules.
English needs `_one` + `_other`. Other locales may need `_zero`, `_few`,
`_many`, `_two`. The translation script automatically generates whichever
variants the target language needs.

```json
{
  "common.trash.empty-confirm_one": "This will permanently delete 1 item.",
  "common.trash.empty-confirm_other": "This will permanently delete {{count}} items."
}
```

Caller side:

```ts
t('common.trash.empty-confirm', { count: items.length });
```

The locale inventory test covers shard key parity. Plural usage remains
covered by the normal locale coverage tests.

## Interpolation

Use `{{name}}` placeholders. Translators must keep them verbatim. The
translation script's system prompt instructs the model to preserve them.

```json
{ "common.trash.delete-confirm": "This will permanently delete \"{{name}}\"." }
```

## `<Trans>` markers

For strings with embedded React components (links, bold, keyboard chords),
wrap with `<Trans>` and use short marker tags. The translation script's
prompt preserves these tags verbatim.

Convention: single-letter or two-letter lowercase tags so translations stay
readable and the marker is unambiguous.

| Tag | Meaning |
|---|---|
| `<s>` | strong / bold |
| `<a>` | link (`href` lives on the React side) |
| `<c>` | code or kbd snippet |
| `<k>` | keyboard chord (e.g. `Cmd+K`) |
| `<br/>` | hard line break |

Example:

```tsx
<Trans i18nKey="onboarding.step-3.body">
  Open the <s>Files</s> tab and press <k>Cmd+N</k> to create your first note.
</Trans>
```

## Lock mechanism (Group V)

Human reviewers can mark a translation as locked so the LLM script will not
overwrite it on the next run. Metadata is stored at the same nesting level
as the translation, with double-underscore-prefixed sibling keys
(`__sourceHash`, `__locked`). The double-underscore prefix is deliberate:
kebab-case forbids underscores in real translation keys, so these markers
can never collide with real content.

```json
{
  "settings": {
    "api-keys": {
      "title": "Llaves API",
      "title__sourceHash": "9e1f...",
      "title__locked": true
    }
  }
}
```

`scripts/translate-i18n.mjs` discovers the base plus every feature shard,
skips any key with `__locked: true`, and also
skips keys whose `__sourceHash` matches the SHA-256 of the current English
string (no source change, no re-translation).

## Regenerating translations

```bash
# 1. Edit the owning feature's locales/en.json (or the shared base for shell copy).
npm run extract-i18n

# 2. Audit the shard diff. The inventory test discovers it automatically.
npm run test -- en-json-snapshot

# 3. Regenerate matching es.json + de.json shards. Hash-incremental: only changed keys hit the API.
ANTHROPIC_API_KEY=sk-ant-... npm run translate-i18n

# 4. Commit the three locale files for the feature together.
```

Re-running with no English changes is a no-op (zero API calls, zero diff).

## Completeness gate

`npm run i18n:completeness` (`scripts/i18n-completeness-check.mjs`) fails the
build if any base or feature `de.json` / `es.json` shard is missing (or has an
empty value for) an English leaf key. It runs as a blocking step in `npm run gate` —
separate from the report-only `i18n:check` (which only verifies keys used in
code exist in an English catalog, per KNOWN-I18N-01; it says nothing about whether
de/es actually translated them). This is what stops the "a new feature ships
English-only for German/Spanish users" class of bug: forgetting step 3 above
now fails the gate instead of shipping silently.

If a key is genuinely meant to stay English in every locale (a fixed brand
name, a legal term), list it in `src/locales/i18n-completeness-allowlist.json`
(create the file if it doesn't exist) as `{ "the.dotted.key": "one-line reason" }`.
There is no allowlist by default — every key is required in every locale.

## Cost cap

The translation script aborts before sending if estimated total tokens
exceed the limit (default 5,000,000 ≈ $15 at Sonnet rates). Override with
`--max-tokens=N`. Cost depends on the shards whose English source changed.
