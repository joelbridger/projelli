Security and data handling.

Updated 2026-06-08 · Forwardable to a CCO, IT reviewer, or malpractice carrier

The short version. Your documents and data are stored on your machine. Your API key is in your OS keychain. AI requests go directly from your machine to your chosen provider. Keepance's servers are not in the data path. With a local model such as Ollama, nothing leaves your machine at all. This page states our current posture honestly, including what we don't have yet.

This page is written for attorneys, CPAs, consultants, and the IT or compliance staff who review tools on their behalf. It covers where data is stored, who can see it, how API keys are handled, what the audit trail looks like, and what certifications and agreements we currently hold (and don't). If you have a specific technical question not answered here, email security@keepance.com.

What Keepance does with your data

Documents stay on your machine

Keepance stores all your notes, drafts, chat histories, and workspace files as plain files in a folder you choose on your own hard drive. No Keepance server holds a copy.

API keys in your OS keychain

When you configure a cloud AI provider, Keepance stores your API key in the OS keychain: macOS Keychain, Windows Credential Manager, or Linux libsecret. Keys are never written to a config file in plaintext and never transmitted to Keepance's servers.

AI requests go directly to your provider

When you send a message to a cloud AI provider (Anthropic, OpenAI, Google), the request travels from your machine directly to that provider's API using your key. Keepance's servers are not in this path and never see the content of your prompts or responses.

Local model option: nothing leaves your machine

When you configure Keepance to use a local model (such as Ollama running on your machine), AI inference runs entirely on your hardware. No data reaches any external server. This path is available to any Keepance user and is the appropriate choice for content that must not leave your machine. Note: cloud BYOK keys still send your prompt to the cloud provider; only the local model path produces zero external egress.

Email stays local and encrypted at rest

If you use Keepance's email import feature, imported messages are encrypted at rest on your device and searchable locally. Email is never routed through a Keepance server.

Append-only audit log

Keepance writes an append-only log of every AI action: timestamp, model, files included, and output produced. The log lives on your machine, is per-workspace, and can be produced for any matter on request. It is retained as long as your workspace folder exists.

Telemetry is opt-in; default is nothing

The Keepance desktop app collects no usage telemetry by default. If you choose to enable anonymous usage reporting in Settings, it can be turned off at any time. The marketing site uses Plausible Analytics (no individual tracking, no cookies).

What the data flow actually looks like

Two paths are possible depending on which AI provider you configure:

Path A: Cloud provider (Anthropic, OpenAI, Google) with your API key

  1. You type a prompt in Keepance.
  2. Keepance reads your API key from the OS keychain.
  3. Your machine sends the prompt directly to the provider's API endpoint, under your account.
  4. The provider returns a response directly to your machine.
  5. Keepance saves the conversation to a file in your workspace folder.

Who has a copy: you and the AI provider. Keepance is not in this path.

Your prompts are governed by your chosen provider's API data-processing terms, not consumer product terms. Neither Anthropic nor OpenAI uses API inputs to train models by default. See each provider's current API usage policy for the precise retention and data-handling terms.

Path B: Local model (Ollama or similar)

  1. You type a prompt in Keepance.
  2. Keepance sends the prompt to the local model running on your machine (typically at localhost:11434 for Ollama).
  3. The model generates a response on your hardware.
  4. Keepance saves the conversation to a file in your workspace folder.

Who has a copy: you. No network call is made.

This is the strictest posture available. Nothing reaches any external server. If your professional obligations, an NDA, or client instructions prohibit any external data transmission, the local model path meets that requirement literally.

What Keepance's servers do handle

A few narrow functions do go through Keepance infrastructure:

  • License validation. When you activate a license, Keepance checks your license key against our license server (LemonSqueezy). This call contains your license key only, not your workspace data.
  • Update checks. The app periodically checks GitHub Releases for a newer version manifest. This is a GET request that contains no user data.
  • The web demo (keepance.com homepage). The five-message demo on the marketing site runs through a Keepance-managed proxy that holds a shared API key. This exists so visitors can try the interface without an API key. The desktop app does not use this proxy once you install it and add your own key. Do not put client data into the web demo.

That is the complete list. Everything else stays on your machine.

Key storage

Keepance uses the OS-native keychain to store API keys:

  • macOS: macOS Keychain (the same store used by Safari and 1Password).
  • Windows: Windows Credential Manager.
  • Linux: libsecret (GNOME Keyring or KWallet depending on your desktop).

Keys are never written to application config files in plaintext, never logged, and never included in any diagnostic or crash report. If you delete the app, the key remains in your keychain under your control and must be removed from there if you want it gone.

What we don't have yet

Current gaps: honest disclosure for reviewers

  • No SOC 2 certification. Keepance has not completed a SOC 2 Type I or Type II audit. We do not hold any active SOC 2 report. We are evaluating whether to pursue this; the SOC 2 question in the FAQ below explains our thinking. If SOC 2 is a hard requirement for your vendor approval process, we cannot satisfy that requirement today.
  • No signed DPA. We do not have a standard signed Data Processing Agreement available for customer execution yet. A draft template is in preparation and under legal review. If your organization requires a signed DPA before procurement, contact legal@keepance.com and we will update you on timeline.
  • No penetration test report. We have not commissioned an independent third-party penetration test. The codebase is open source at github.com/keepance/keepance and can be reviewed directly.
  • No enterprise SSO / SAML. Keepance is a single-user desktop application. There is no enterprise directory integration today.

We believe being direct about these gaps is more useful than burying them. The security story for Keepance is architectural: most of the threats that SOC 2 and a DPA guard against (unauthorized access to vendor servers, vendor breach, data shared with third parties) are substantially reduced by having no vendor servers in your data path to begin with. That's a meaningful substitute posture, not a compliance certification. They are different things, and we're not going to pretend otherwise.

Frequently asked questions

Can Keepance read my documents?

No. Your documents are stored as files on your hard drive in the folder you chose. Keepance does not upload them to any server. The app reads them locally to display them in the editor. The only time any content leaves your machine is when you send a specific message to a cloud AI provider, and at that point it goes directly to the provider under your account, not through Keepance.

If I use Anthropic as my AI provider, does Anthropic train on my prompts?

No. The API tier (which is what BYOK tools like Keepance use) does not train on inputs by default per Anthropic's commercial API terms. This is different from Claude.ai consumer accounts, which have different terms. Read Anthropic's Commercial Terms of Service for the current precise language.

What if I want literally nothing to leave my machine?

Use the local model path. Configure Keepance to use Ollama with an open-weight model (Llama, Mistral, Phi, or similar) running on your hardware. With a local model configured, Keepance makes no outbound AI calls. Your prompts are processed entirely on your machine. This is the appropriate setup for content that must not reach any external server, period.

Is there a server-side copy of my workspace?

No. There is no cloud sync, no backup to Keepance's servers, and no account-linked storage. Your workspace exists only in the folder you chose on your machine. If your hard drive fails and you have no local backup, your workspace is gone. We recommend disk encryption (FileVault on macOS, BitLocker on Windows) and a local backup routine on top of Keepance.

What is in the audit log?

The append-only audit log records: timestamp, AI model used, the list of files included as context, and the output produced. It does not capture the full prompt text by default (that is in the .aichat file). The log is per-workspace, stored on your machine, and can be exported as plain text. It is retained as long as your workspace folder exists.

Do you have a Data Processing Agreement?

Not a finalized, signed version yet. A draft template is in preparation under legal review. If you need a DPA for vendor approval, email legal@keepance.com. Because Keepance does not process your data on its servers (it's stored on your machine), the traditional DPA framing that governs a cloud SaaS processor does not apply cleanly to our architecture. We'll work through the appropriate framing with counsel.

Do you have SOC 2?

No. We do not hold a SOC 2 report today. If you need to understand our controls in detail, the source code is open at github.com/keepance/keepance. The short architectural answer: a SOC 2 audit focuses heavily on controls around a vendor's server-side data processing. Because we don't process your data server-side, most of the controls an auditor would test simply don't apply. We're evaluating whether to pursue an audit scoped to the parts that do (license server, update server, web demo proxy). That's a cost and timeline decision that isn't finalized yet.

What happens to my data if Keepance shuts down?

Nothing changes. Your files are on your machine in plain Markdown and .aichat (JSON) format. They don't move. If Keepance disappears tomorrow, you still have your files, readable with any text editor. This is a deliberate design choice: your data should outlive the tool.

Do you support multi-user or enterprise deployments?

The Practice tier licenses up to five seats on the same machine or within one organization, but each instance runs independently as a desktop app. There is no centralized server, no shared database, no SSO, and no admin console today. Enterprise directory integration (SAML, LDAP) is not on the current roadmap. If that's a requirement, we aren't the right fit yet.
