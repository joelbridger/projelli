## Scope — the outbound guards
1. **E3-gate — unresolved notes can never ship.** A meeting note in needs-review/unresolved state (incl. notice-quarantined under Strict) must be structurally unsendable: "Send to Wealthbox" and "Draft follow-up" disabled-with-honest-explanation on such notes ("Review this note first — it hasn't been checked"). The AI-apology-as-note case (a note whose generation errored/was flagged) must never be queueable. Tests: each unresolved state → outbound affordances disabled + explain; resolved → enabled.
2. **E3-provenance — AI-drafted content carries its origin.** CRM notes written via the review card get an appended provenance line ("Drafted by Advisor Prep Hero AI from the [date] meeting; approved by [advisor] on [date]" — honest, compact, localized); the firm-tier compliance-note checkbox (R5) defaults ON (solo tier keeps user choice, remembered). Tests incl. wire-level (the Rust write includes the line).
3. **R4a — no generate-on-open.** DraftFollowUpModal must NOT resolve the provider/send content on open — content leaves only on an explicit Generate click. The modal opens instantly with a preview of what WILL be sent (which note, which scope) + the destination (provider name), then generates on click. Egress logging moves to the actual send.
4. **R4b — citations travel with the draft.** Saved/exported follow-up drafts retain their citation footnotes (source names, not internal IDs); what the advisor saw in the modal is what lands in the saved artifact.
5. **R6 — whole-practice pre-send truth.** Before a whole-practice Ask sends in cloud mode: one confirm — "This sends brief summaries of N clients to [provider]. Continue?" (N computed, provider real, remembered-choice checkbox allowed but default ask). Test: N and provider correct; local-only mode skips the dialog.
6. **R1 — attestation stays deliberate in all-party states.** In all-party-consent states (or unknown/two-party default), the consent checkbox NEVER pre-checks from standing consent; one-party states may keep the convenience. Uses the existing recordingConsentLaw model. ⚠️ ConsentDialog is currently owned by the noticecard lane — implement this as a small, clearly-marked change and COORDINATE: check `git log ~/lp-noticecard` state before touching; if noticecard has uncommitted ConsentDialog work in flight when you get there, ask me (`COORDINATOR:`) and I'll sequence you. Everything else in this brief is collision-free.
7. **R9-interim — biometric consent before voiceprint enrollment.** "Separate speakers" enrollment gets an explicit consent step naming what it is (a voice profile of the CLIENT, stored encrypted locally) and requiring affirmative confirmation the client consented — ledgered like other consent events. Honest note that some states regulate voiceprints ("check your state's biometric rules — not legal advice", consistent with the existing consent-law disclaimer posture).
