## Why CORS + Tauri plugin-http both, not one

- **Tauri-prod build** uses `@tauri-apps/plugin-http` (Rust-side fetch) — bypasses browser CORS entirely. Needs the URL in the `http:default` capability scope.
- **Tauri-dev (`npm run tauri dev`)** uses native fetch from `tauri://localhost` origin. CORS applies → form-handler must send `Access-Control-Allow-Origin: *`. CSP `connect-src` must include the URL.
- **Browser dev (`npm run dev` + `?testMode=true`)** also uses native fetch. Same CORS requirement.

The selector logic lives in `src/modules/models/fetchUtils.ts` → `getCorsSafeFetch()`. Reuse it for any new endpoint that has to be reachable from both modes.

## Form-handler integration cheatsheet

The form-handler is a *shared* multi-tenant service. To add a new Projelli form in a future session:

1. Edit `~/services/form-handler/server.ts`, add to `SITES.projelli.forms`:
   ```ts
   "your-form-id": { name: "Projelli - Your Form", fields: [...], successMessage: "..." }
   ```
2. POST URL becomes `https://projelli.com/api/forms/projelli/your-form-id` (Caddy proxies `/api/forms/*` from projelli.com → 127.0.0.1:5180).
3. Restart with `sudo systemctl restart form-handler.service`. JSONL output lands in `~/projelli/sign-ups/`. Brevo email goes to `jamesondaines@outlook.com` (best-effort; storage is mandatory).
4. Peer-IP allowlist only accepts loopback + Docker bridges, so Caddy is the *only* legitimate caller. CORS `*` is safe because the IP allowlist is the actual gate.
