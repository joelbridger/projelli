## Key non-obvious things a future session needs to know

### Silent install: `SetSilent silent` is required
Setting `$PassiveMode = 1` in `.onInit` does nothing by itself. You must also call `SetSilent silent` (runtime directive) to actually skip the MUI wizard pages. See `src-tauri/windows/installer-silent.nsi` lines 453-470. The reverse path for `/INTERACTIVE` is `SetSilent normal`.

### Radix DropdownMenu + HTML5 drag = incompatible
`DropdownMenuTrigger` opens the menu on `pointerdown`, which captures the pointer and kills the browser's drag gesture heuristic on any `draggable` child. We tried every workaround (`modal={false}`, preventDefault on pointerdown, DropdownMenuAnchor) — none worked cleanly. The fix was to replace Radix with a custom portal popover on the group chip specifically. Other DropdownMenus in the app (e.g., the tab bar overflow menu at the far right) are fine because nothing inside them is draggable.

Pattern for draggable-with-popup:
```tsx
// Plain Button with draggable + onClick; no Radix trigger.
<Button draggable onDragStart={...} onClick={(e) => {
  const rect = e.currentTarget.getBoundingClientRect();
  setAnchorRect({ top: rect.bottom + 4, left: rect.left });
  setOpen(true);
}}>...</Button>

// Popup portaled to body with position: fixed + captured coords.
{open && createPortal(
  <div role="menu" style={{ position: 'fixed', top: anchorRect.top, left: anchorRect.left, zIndex: 50 }} ...>
    ...
  </div>,
  document.body,
)}
```

Click-outside + Escape via document-level listeners attached while `open === true`.

### Tab rendering is order-driven, not group-driven
Earlier versions forced all group chips to the left and ungrouped tabs to the right. R3 changed this. `renderItems` in `TabBar.tsx` walks `openTabs` in order and emits a chip on each group's **first** appearance (tracked by a `seenGroups` Set). `tabGroups` array order is irrelevant for display; the visual order derives from where each group's tabs sit in `openTabs`.

Consequence: to reorder a group visually, you move its tabs as a block within `openTabs`. See the `reorderInTabBar` store action.

### Drag payload prefixes
- Tab drag: `text/plain = "<numericIndex>"`
- Group drag: `text/plain = "group:<groupId>"`
- TabGroupManager row: `text/plain = "tabgm:<path>"`

Drop handlers branch on payload prefix. Tab drop targets ignore group payloads that don't match their zone semantics, etc. If you add a new draggable surface, follow the prefix pattern.

### Mock workspace (dev-mode) FS parity
`src/App.tsx` ~line 418 defines an in-memory mock workspace service active when `?testMode=true`. It implements the full `WorkspaceService` interface including `mkdir`, `list`, `stat`, `rename`, with folder semantics synthesized from key prefixes. Keep this in sync with any new `TauriFSBackend` methods or features will silently fail in dev mode.

### New-file creation does NOT auto-trigger rename
Earlier we tagged file-creation handlers with `setPendingRenamePath(newPath)` to auto-open inline rename. Jameson asked for this to be removed — the `prompt()` dialog that asks for the filename already IS the rename mechanism; opening inline rename again was redundant. The `pendingRenamePath` store flag + TabBar effect remain as infrastructure for future flows that don't prompt, but no creation handler currently uses them.

### File-icon icon in editor title strip
`src/components/layout/MainPanel.tsx` renders the filename header with `getFileIcon(ext)` from `utils/fileIcons.ts` — same icon used in the tab bar + file tree. Keep these three surfaces using the single utility so they never drift.
