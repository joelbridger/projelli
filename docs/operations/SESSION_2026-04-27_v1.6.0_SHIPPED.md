## The full v1.6 RC arc (rc.1 → rc.17 → v1.6.0)

Every RC failure taught the next layer something. **For future sessions debugging similar releases, read this whole arc as a single composite case study** — see `docs/features/V1_6_RELEASE.md` for per-RC line items.

Major fix categories:

1. **rc.1–rc.4** — Windows silent installer + tab/group UX overhaul + auto-launch on install (rc.6+). Stable baseline before Mac dogfood started.
2. **rc.5** — In-app bug-report dialog (rc.4's mailto button → in-app dialog POSTing to form-handler).
3. **rc.7–rc.8** — Mac fs-scope glob bug. The `glob` crate rejects `C:\**` because backslashes aren't path separators in the crate's parser. Replaced with `**/*` (single universal pattern) and forward-slashed deny entries. The session lesson: I shipped rc.7 with a wrong fix because I diagnosed from the error message instead of reproducing locally with `glob v0.3.3`. **Memory: `feedback_reproduce_and_bundle.md` rule 1.**
4. **rc.9** — Fixed two Unix-specific defaults: Tauri plugin-fs's `require_literal_leading_dot` (which made `**/*` skip dotfiles like `.trash`) and the CSP missing `ipc: http://ipc.localhost`.
5. **rc.10** — Anthropic API key validator was POSTing to `/v1/messages` with the retired `claude-3-haiku-20240307` model, returning 404. Switched to `GET /v1/models`. Plus a CSS Grid `min-w-0` fix on PromptDialog so long workspace paths stop expanding the modal beyond its `max-w-lg` cap.
6. **rc.11–rc.12** — Apple notarization rejected the build because the embedded MCP sidecar inside the .app's Resources wasn't signed. Tauri's outer codesign call only signs the top-level bundle. Added an explicit codesign step before tauri-action runs.
7. **rc.13–rc.14** — `LicenseSettings` component existed in the codebase but was never imported into `SettingsModal`, AND `'license'` wasn't in the `visibleCategories` auto-add list, so the nav button never rendered.
8. **rc.15** — License panel could finally render, but activate threw "Network error: Load failed" because `https://licenses.projelli.com` wasn't in CSP `connect-src` or `http:default` capability scope.
9. **rc.16–rc.17** — `arduino/setup-protoc@v3` started returning empty arrays for authenticated GitHub API calls (passing `repo-token`). Replaced with native package managers (brew/apt/choco) which bypass the API entirely.
10. **Server-side fixes during the rc.17 dogfood** (no rebuild required):
    - License validator was missing CORS preflight handling — added `OPTIONS` handler returning 204 with the right `Access-Control-Allow-*` headers, plus a `withCors()` wrapper for all responses.
    - License validator was calling LemonSqueezy `/v1/licenses/validate` instead of `/v1/licenses/activate`. New licenses default to `status="inactive"` until first activation, so /validate alone always returned `license_not_active`. Fixed by using LS /activate API on first touch, idempotent for the same `instance_name`.
    - Tier mapping was checking `variant_name` only, but LS users who don't customize the variant get `variant_name: "Default"` and the actual product identity lives in `product_name` (e.g. "Projelli Founder's Launch"). Updated `tierFromVariantName()` to check both fields.

## Permanent infrastructure now in place

These are the pieces buyers + future Claude sessions can depend on:

- **`license-validator.service`** — systemd Bun service at `~/services/license-validator/server.ts`, listening at `licenses.projelli.com`. Endpoints: `/healthz`, `/activate`, `/validate`, `/webhook`. Configured with `LEMONSQUEEZY_API_KEY`, `LEMONSQUEEZY_STORE_ID`, `LEMONSQUEEZY_WEBHOOK_SECRET` in `/etc/license-validator.env`. Stores activation records in `~/services/license-validator/data/activations-YYYY-MM.jsonl`.
- **Cloudflare-tunnel-routed domains:** `licenses.projelli.com`, `projelli.com`, `projelli.lemonsqueezy.com` (their CNAME), `analytics.jamesondaines.com`.
- **`tauri.conf.json` allowlists:** CSP `connect-src` includes the four AI provider domains, `https://projelli.com`, `https://licenses.projelli.com`, and `ipc: http://ipc.localhost`. `capabilities/default.json` `http:default.allow` mirrors the same external endpoints. Both are required because Tauri-dev uses webview fetch (CSP) and Tauri-prod uses plugin-http (capability scope).
- **CI workflow:** `.github/workflows/release.yml`. Fires on git tag push. Matrix builds for Mac aarch64 / Mac Intel / Linux + a separate `build-windows` job. Mac/Linux use `tauri-action` with notarization re-enabled (env vars uncommented). Windows uses Azure Trusted Signing as a separate step. **Known quirk:** the matrix typically produces 2-3 draft releases per tag (one per Mac arch + one for Linux) which need to be manually consolidated into one. Same script in this session's history works every time.
- **Manual Windows updater-sign procedure** at `SESSION_2026-04-16_v1.0.8_SHIP.md` — needed every release until UX-42 ships. Sign Windows installer with `~/.projelli-secrets/updater.key` to produce `.exe.sig`, then patch `latest.json` to add the `windows-x86_64` entry.
