# Keepance onboarding — V2 "concise" (4 screens)

A clickable, **vector-crisp** animated first-run onboarding for Keepance, built as
standalone HTML scenes (no video, no build toolchain, no React). This is the
**radically concise** rewrite: **1 intro + 3 action screens**, where every screen after
the intro asks the user to do one real thing (pick an AI mode, connect data, ask a
question) rather than just reading a slide.

It supersedes the 12-scene version (kept in `../onboarding-prototype`, still live on :8902
for side-by-side comparison). The rationale for every cut and fold is in **`CRITIQUE.md`**
next to this file.

**Status:** design draft for Jameson to react to and iterate. NOT yet integrated into the app.

**Audience:** financial advisors (the 2026-06-24 re-aim). Organizing unit = a client /
household. Hook: *"a private AI that actually knows your clients."*

`serve_nocache.py` exists for a reason: a plain `python -m http.server` sends no
cache headers, so browsers heuristically cache the scene files and show a **stale**
version (this caused a confusing "double logo" bug). This server sends `no-store`.

## Edit / regenerate

Everything is generated by one script. Edit the copy/scenes/styles there, then rebuild:

```bash
cd ~/keepance/docs/design/onboarding-prototype-v2-concise
python3 build_live.py        # reads ./assets, writes a complete servable site to ./dist
```

- `build_live.py` — the **single source of truth**. Scene copy, CSS, animation timeline,
  and the interactive shell all live here as Python strings.
- `assets/` — brand assets the generator copies into `dist/`: Sora fonts, `keepance-logo.svg`,
  and real SVG/PNG logos for the partner software (`logos/`).
- `dist/` — generated output (git-ignored; not committed). Run `build_live.py` to create it;
  the source above fully reproduces it.

## Architecture (why it looks the way it does)

- **Live HTML, not video.** The composition is HTML/CSS/GSAP. Earlier attempts rendered it
  to MP4 (via HeyGen HyperFrames) — Jameson rejected that: video text is **fuzzy** and not
  interactive. Live HTML is vector-sharp and clickable. *Lesson: render→MP4 is marketing
  only; ship live HTML for anything in-app.*
- **One scene = one HTML file** (`dist/scene-N.html`), each a fixed 1920×1080 `#stage`
  self-scaled to the window. GSAP plays an entrance animation per scene.
- **An interactive shell** (`dist/index.html`) holds an `<iframe>` and swaps its `src` to
  advance scenes, with overlaid nav (Back / Continue / progress dots / Skip).
- **Contained nav.** The whole experience is locked inside a centered 16:9 box. Nav lives
  in a 1920×1080 layer scaled to match the box, so buttons/dots sit *inside* the
  presentation and scale with it.
- **Persistent background + corner logo.** The colored gradient backdrop AND the small
  top-left logo live in the **shell**, behind/over the iframe — NOT inside each scene.
  This is deliberate: if they lived in each scene they'd reload and **flash** on every
  advance. Only the scene's text/cards animate in. The corner logo fades in once after the
  welcome screen, then stays put.
- **Anti-flash + safety net.** Animated elements start at `opacity:0` in CSS so they never
  paint before GSAP hides them; a `setTimeout` failsafe reveals everything even if a
  background/streamed tab throttles `requestAnimationFrame` and freezes the animation.
- **Cache-busting.** Scene links carry `?v=<timestamp>` regenerated each build, so a reload
  always fetches fresh scenes.

## The 4 screens (in order) — current (round 3)

1. **intro** — headline hook + a simple 3-step **flowchart** with **animated Lottie icons**
   (Connect your AI and files -> Keepance builds Client Maps -> Ask anything, with sources)
   and three security **pills**: "Keepance stores zero of your data", "Encrypted", "Cloud
   providers are SOC 2 + enterprise-grade" (SOC 2 is the AI provider's, NEVER Keepance's).
   Button: "Go!". Icons are free-licensed Lottie (see `SOURCES.md` + `assets/lottie/`).
2. **power** — "Connect your AI": two options. Card 1 "Use ChatGPT, Claude, or Gemini" leads
   with accurate bullets (Keepance never sees your key/data; providers SOC 2 Type 2; encrypted
   in transit + at rest; providers don't train on your data on paid API usage). Clicking it
   expands to a simple 1-2-3 get-a-key flow (free to create, pay as you go, real provider link),
   the key field, and an "I need help setting this up" link (SHOWN ONLY; real action = help
   ticket/email, wired in a separate session). Card 2 "Use local AI". No "recommended" steer.
3. **connect** — "Securely connect your data": the three REAL connectors only (Files
   OneDrive/local, Email Outlook/Gmail, Wealthbox). Accurate note that reports from other
   tools "arrive as files" (Keepance does not integrate with RightCapital/Holistiplan/etc.).
4. **setup** — live progress: AI status (downloading on-device AI, or "Connected" for cloud),
   per-source import bars (email / Wealthbox / files), a "Building your Client Maps" indicator
   (the wow: assembling the firm's story), a preview of questions you'll be able to ask, and
   Skip / Continue. Replaces the earlier "Ask your first question" aha screen.

## Copy + brand constraints (honor these when editing)

- **No em dashes** in any user-facing copy. (Code/comments are fine.)
- **Never claim "compliant" / "guaranteed."** State the mechanism precisely: a local model
  (data never leaves the machine) vs. bring-your-own cloud key (goes direct to the provider,
  never through Keepance).
- Avoid the banned marketing words: leverage, delve, seamless, transform, empower, elevate,
  unlock.
- **Light theme only.** Brand hex: navy `#0A2540`, blue `#5DC6FF`, pink `#FF3CE8`. Font: Sora.
- **Do not hand-draw graphics** — Jameson (a product designer) rejected hand-built CSS/SVG
  illustration as amateur. This prototype stays with type, brand gradient, and real logos;
  any illustrated/character motion should come from a designer tool (Rive/Lottie), not me.
