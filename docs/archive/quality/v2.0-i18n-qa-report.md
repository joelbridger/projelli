# v2.0 i18n QA Report

Status: **stub awaiting Jameson's eyeball pass.**

This report is the manual sign-off for Stream E (Spanish + German localization). Automated coverage runs in `npm run test` (locale-coverage, locale-smoke, en-json-snapshot, locale-detect). The items below need a human looking at pixels.

## How to fill in this report

1. Run the app locally: `npm run dev`.
2. Switch to Spanish: Settings (gear icon) → General → Language → Español. Verify all UI updates instantly with no reload.
3. Walk every section under "Surfaces to check" below. For each, mark Pass / Fail / Note in the table.
4. Repeat for German (Deutsch). German is the primary risk locale because German nouns and compound words tend to be 30-50% longer than their English counterparts. Look for truncation in buttons, sidebar labels, dialog titles, and any fixed-width container.
5. When a string looks wrong, edit `src/locales/<locale>.json` directly and run `node scripts/lock-translation.mjs <locale> <key>` to protect your edit.

## How to run the Playwright locale matrix

The matrix lives in `playwright.config.ts` as four projects: `chromium` (existing English baseline, do not break), `en`, `es`, `de`. The locale projects override `baseURL` to include `?lang=<locale>`, which `src/main.tsx` picks up before first paint.

Run the smoke spec across the three locale projects:

```bash
npx playwright test i18n-locale-matrix --project=en --project=es --project=de
```

Run the entire E2E suite across the matrix (heavy; expect minutes):

```bash
npx playwright test --project=en --project=es --project=de
```

Run a single locale:

```bash
npx playwright test --project=es
```

Visual regression is project-scoped: snapshots taken under `--project=es` are stored separately from `chromium`'s, so the existing English baselines are not at risk. To capture per-locale baselines for the first time, run with `--update-snapshots`.

## Surfaces to check

For each locale, walk these surfaces and tick off the table at the bottom.

### A. App shell

- Sidebar primary tabs (Files, Search, Workflows, AI Assistant, Research, Whiteboard, Audit, Trash). Are labels truncated when the sidebar is collapsed? When expanded?
- Status bar at the bottom (autosave indicator, line/column, mode).
- Workspace selector dialog (first-launch screen).
- Welcome / onboarding cards.

### B. Editor

- Tab bar with multiple open files. Long German file names plus the "modified" indicator dot.
- Editor toolbar overflow on narrow viewports.
- Right-click context menu in the editor.
- Find / replace panel labels.

### C. Settings

- Every settings panel reachable from Settings (gear icon): General, API Keys, Models, Appearance, Plugins, About, etc.
- Confirmation dialogs (e.g. "Reset to defaults", "Sign out", "Delete data").
- The Language picker itself (in General tab).

### D. AI Assistant

- Chat input placeholder.
- Streaming indicator labels ("Thinking", "Tool call", etc.).
- Stop button.
- Model selector dropdown.
- Empty state when no chats exist yet.
- Provider warning toast when API key is missing.

### E. Workflows / Research

- Workflow launcher panel: every template card title + description.
- Run record viewer headers and column titles.
- Source card form labels.
- Citation popovers.

### F. Marketplace

- Templates tab: search input, filter chips, install button states.
- Plugins tab: same.
- Detail views: long descriptions wrapping correctly.

### G. Trash + Audit

- Trash panel: empty state, "Restore" / "Permanently delete" actions, confirmation dialogs.
- Audit log: filter labels, action verbs in the entry list.

### H. Toasts and errors

- Save success / failure toasts.
- Network error messages.
- Permission denied messages.
- File operation undos ("Undo: deleted X.md").

### I. Dates / numbers / plurals

- Anywhere a count appears: "1 file" vs "5 files" (English `_one` / `_other`). Spanish uses the same pair; German also uses `_one` / `_other`. Verify the right variant fires.
- Relative dates ("just now", "5 minutes ago", "yesterday"). If these aren't yet wired through `Intl.RelativeTimeFormat`, note it.
- Number formatting in any inputs that accept numbers: 1.234,56 vs 1,234.56. Editor content stays as-typed (per spec); UI labels should follow locale.

## Eyeball checklist (per spec §8.7)

For each surface above, in each locale, check:

- [ ] No raw key strings rendered (e.g. `chat.input.send-button` showing literally instead of "Enviar").
- [ ] No empty buttons or labels.
- [ ] No text overflowing its container.
- [ ] No text truncated with ellipsis where the original English fit fully.
- [ ] No untranslated English bleeding through (a few brand names like "Keepance", "Claude", "OpenAI", "Anthropic", "Markdown" should stay English; everything else should translate).
- [ ] No mojibake or broken Unicode (ñ, ü, ß, accented characters render correctly).
- [ ] Plurals use the right form for the count.
- [ ] Dates and times read naturally for the locale (no "January 5, 2026" in German).
