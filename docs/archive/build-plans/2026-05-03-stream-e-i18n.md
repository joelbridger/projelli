# Projelli v2.0 Stream E: i18n + Spanish + German Translations

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship v2.0 with full English + Spanish + German UI localization. Tooling, ESLint enforcement, complete string-extraction sweep, LLM-translated locale files (with Jameson's optional light review pass), locale detection at first launch, in-app language picker, and a QA sweep across all three locales. After this stream merges, every UI string in Projelli renders correctly in `en`, `es`, and `de`.

**Branch:** `feature/stream-e-i18n`. Branches off `master`. Per spec: **Stream E gates LAST.** All other streams must merge before E starts the extraction sweep, otherwise the sweep would fight with concurrent UI work.

**Why E gates last:** the string-extraction sweep (E2) touches every React component file with hardcoded JSX text. Concurrent UI work in other streams = merge conflicts on every component. Per spec §8: "Stream E gates on all other streams merging to main." The custom ESLint rule (added in E1) DOES run from day one as a CI gate, but actual extraction waits.

**Architecture:**
- **`i18next` + `react-i18next`** for runtime translation.
- **`i18next-parser`** for static extraction.
- **Custom `eslint-plugin-projelli-i18n`** rule detects JSX text content with 3+ alphabetic words not wrapped in `t()` or `<Trans>`. Errors in CI.
- **Locale files** at `src/locales/{en,es,de}.json`. English is source-of-truth.
- **LLM translation script** at `scripts/translate-i18n.mjs` produces es.json + de.json from en.json. Hash-based incremental: only re-translates changed keys. Lock mechanism preserves human-edited strings.
- **Locale detection** via Tauri `os.locale()` on first launch (web demo uses `navigator.language`); user override via Settings → Language picker.

**Tech Stack:** TypeScript 5, React 18, i18next 23, react-i18next 14, i18next-parser 9, Anthropic SDK (for translation script), Vitest, Playwright (for QA sweep).

**Spec reference:** `docs/superpowers/specs/2026-04-28-v2.0-mega-release-design.md` sections 3.4 (key-extraction convention) and 8 (Stream E entirety).

## Group II: String Extraction Sweep (E2)

This is the LONG POLE. Touches every component file with JSX text.

**Approach (per spec §8.3):**

1. Run `i18next-parser` in extract-only mode. Builds initial `en.json` skeleton.
2. Use the custom ESLint rule with `--fix` if possible (or report mode) to flag every hardcoded string.
3. Sweep agents visit each flagged location, pick a key per naming convention, wrap the string in `t()`, add the key to `en.json`.
4. Tricky cases (interpolation, plurals, conditional strings) handled with `<Trans>` or namespace conventions.

**Naming convention:** `<page>.<component>.<element>` lowercase kebab-case. Examples: `chat.input.send-button`, `settings.api-keys.title`, `marketplace.templates.install-cta`.

## Acceptance criteria

- App launches in `en`, `es`, `de` without missing-key errors.
- User can switch language via Settings; UI updates without reload.
- First-launch locale detection picks the OS language if supported, falls back to `en`.
- All E2E tests pass in all 3 locales.
- ESLint rule blocks new hardcoded strings in CI.
- Translation script is reproducible + hash-incremental + cost-capped.

---

## Risks and mitigations

| Risk | Mitigation |
|---|---|
| Sweep introduces regressions | ESLint rule + i18next-parser CI gate; full E2E suite across all locales. |
| German layout breaks on small viewports | Visual regression tests; manual eyeball; min-width fixes in CSS. |
| LLM mistranslates idiomatic UI phrases | Light human review (E5); community reviewers post-launch; lock mechanism. |
| Cost overrun on re-translation | Hash-based incremental; cap at $5/run. |
| Plurals/genders differ | i18next CLDR plural rules + manual review. |
| Dates/numbers feel "wrong" | Use i18next's `Intl.*` formatter integration; review during QA. |
| Stream E merges last; late discovery of missing strings | Custom ESLint rule runs in CI for ALL stream PRs from day one (this stream's E1 lands first). |

## Out of scope (deferred to v2.x)

- Languages beyond `en`, `es`, `de` (community can add later via PR).
- RTL languages (Arabic, Hebrew) — needs CSS direction work.
- In-app translation contributor UI — community PRs only for v2.0.
- Number-input localization (1.234,56 vs 1,234.56) for editor content (UI uses i18next intl; user-edited content stays as-typed).
