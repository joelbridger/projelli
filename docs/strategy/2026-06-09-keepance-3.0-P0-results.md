# Keepance 3.0: P0 Gate Results

**Date:** 2026-06-09
**Updates:** the P0 phase of `2026-06-09-keepance-3.0-roadmap.md`.

P0 existed to de-risk the three make-or-break bets before committing the full build. **All three gates passed and were independently verified** (tests run directly, not taken on the subagent's word). The "ignore difficulty / build in-house / firm platform / one big 3.0" plan is now grounded in proven feasibility.

The spike code lives under `spikes/` and seeds the production workstreams; it is not production itself.

## Gate 1: in-house Word track-changes round-trip (WS-A) — PASSED
- **Commit:** `d9468be`. **Spike:** `spikes/docx-roundtrip/` (6 tests pass).
- **Proven:** tracked insertions, deletions, and comments survive a parse to model to serialize round-trip with author/date/text intact; a new revision authored "Keepance AI" inserts cleanly alongside originals; the output is a structurally valid .docx confirmed by three independent parsers.
- **Carry-forward design:** a DOM model (typed in-memory tree) with `quick-xml` + `zip`; preserve-by-default (keep unrecognized parts byte-for-byte so unmodeled features never become data loss). Maps onto `src-tauri/src/commands/docx/`.
- **Open caveat:** live Microsoft Word accept/reject confirmation needs a real Word instance (design-partner validation). Moves, paragraph-mark revisions, and tracked tables are scoped follow-ons, not blockers.

## Gate 2: matter-scoped verified-citation retrieval (WS-B + WS-C scoping) — PASSED
- **Commit:** `8e4c2c7`. **Spike:** `spikes/matter-retrieval/` (10 tests pass).
- **Proven:** cited retrieval over a mixed email + document corpus resolves to the exact source; matter isolation holds even on a deliberately confusable cross-matter query; citation verification distinguishes verified / not-found / matter-mismatch / text-mismatch.
- **Why isolation is airtight:** confirmed against the LanceDB source that `only_if` prefilters before the vector search, so similarity can never surface an out-of-scope row. The one foot-gun (`postfilter`) must never be used on a scoped query.
- **Carry-forward design:** add `matter_id` + `source_id` columns at index time; make the scope parameter required on `rag_retrieve`; enforce scope at three layers (index, query, audit). Encrypt the `.keepance/vectors/` boundary at rest (residual plaintext embeddings + metadata are a data-at-rest risk, not a cross-matter leak).

## Gate 3: conflict-free firm collaboration + WS-F architecture — PASSED
- **Commit:** `d452543`. **Spike:** `spikes/firm-sync/` (5 tests + asserted demo).
- **Proven:** two replicas of a shared matter make concurrent offline edits and converge to identical state with no coordinator, including the same-position conflict case (both edits survive) and tracked-change attribution surviving a concurrent merge.
- **Decisions (full detail in `spikes/firm-sync/DECISION.md`):**
  - Sync: CRDT (Yjs/`yrs`), with Spike 1's document tree itself CRDT-backed and OOXML as the serialization layer. Local-first stays the default; firm sync is a dumb relay of end-to-end-encrypted CRDT blobs.
  - Identity: optional firm OIDC/SSO layered on the accountless local default; per-user and per-matter keychain namespacing.
  - Licensing: an Org as license holder; Seat = signed, revocable (user, machine) binding under a server-enforced limit.
  - Ethical walls: matter is the ACL unit, enforced at four fail-closed layers, the real teeth being cryptographic per-matter key release (screened means screened).
  - Assured backend: a stateless proxy architecturally incapable of persisting request bodies, provable to firms via open source + a CI no-write test + a scoped SOC 2 / pen-test audit + provider zero-data-retention config + a DPA.

## The one open P0 item (needs real-world action)

This cannot be done autonomously; it should start now, in parallel with the P1 build.
